## 体验检查与修复

| 项目 | 发现及结果 |
| --- | --- |
| 主入口和设置 | 0.4.7 的刷新待机、深蓝开屏、Safari 模糊、设置齿轮高亮、底部返回沿用，并用 Chromium 与 WebKit 回归验证 |
| 身份选择 | 原来按 Esc 会直接收起整个大厅，选中身份后重绘会丢焦点。现在 Esc 先收起身份列表，选中后焦点回到选择框。入口页与房间模式切换也恢复触发按钮焦点 |
| 正式开局与预览 | 原先的普通浮层无法保证底下的酒馆和队伍窗口不会获得键盘焦点。改用模态对话框，保留同一套蓝金视觉与循环动效。点击「踏入故事」回到当前流程，预览回到预览按钮，房间结束后清理残留仪式 |
| 小屏确认 | 短视口压缩仪式图标和留白，必要时可滚动。640×320 下确认按钮在可视范围，390×844 下设置和会话窗口可见 |
| 回合与聊天 | 未轮到自己的隐藏火星现在主动暂停，轮到自己才播放。四人测试覆盖聊天到达时行动输入和光标保持、未读、草稿、暗行动与按席位分发个人状态 |

旧版自动开窗、Safari 开屏缺少模糊，以及本轮身份菜单焦点问题均发生在大厅自己的宿主与渲染逻辑里。复用的悬浮球、动画与几何实现不负责决定何时打开、重绘时恢复哪个控件焦点，也不包含三款扩展的 Hub 注册与接管。

## Hub Runtime Compatibility：未接入

Hub 1.1.0 先启动和联机大厅先启动均实测。两个顺序下大厅独立球各一只，手动开关正常。Hub 运行列表没有 `miemie.multiplayer-lobby`，请求从 Hub 打开失败。同一环境下 API 2 对照扩展能够注册，故该结果不是测试中的 Hub 未启动。

其他三款扩展通过 `extensions.provide()` 注册，使用 Surface、原生窗口入口和释放回调，共用一份业务实例。大厅当前只有独立挂载及页面清理逻辑；蜂窝入口、Hub 启停管理、独立悬浮球交接尚未接入。若做适配，应先把主大厅接入 API 2，明确 Hub 面板关闭、脚本停用及卸载时的房间语义。重点验收 Hub 重载、主大厅与行动／聊天窗口的前景切换、输入草稿与已有房间，以及临时生成钩子的清理。简单同页运行不覆盖这些场景。

## Managed Package Compatibility：未接入

在 Hub 1.1.0 校验器中，三款参考扩展的本地正式包通过其元数据、整包和脚本内容摘要校验。当前大厅 JSON 即使在测试中补齐匹配的外部元数据，也因内容缺少首行构建身份被拒绝，错误类别为 `identity`。测试用的数据没有写入安装包。

大厅当前提供酒馆助手手动导入，缺少正式 Manifest、构建身份、机器更新元数据和经验证的正式发行来源。Hub 在线安装、更新、卸载均不可用。要支持这条分发路径，须另行实现 Package v1，并验收安装、数据保留更新、卸载和错误包拒绝。运行时与包管理分别通过后才能写入相应支持结论。
