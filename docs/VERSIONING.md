# 版本规范

新产品版本只使用无前导零的 `MAJOR.MINOR.PATCH`。禁止 alpha、beta、dev、hub、build 后缀及加号元数据。
PATCH 用于修复与小范围改进，MINOR 用于新增功能或阶段版本，MAJOR 按批准的兼容性决策升级。Git Tag 为 `v<version>`；Pre-release 是 GitHub 状态，不是版本字符串。

唯一版本源为 package.json。锁文件必须一致；构建器在生成前校验格式与身份，脚本名称、ASCII 安装文件名及 UI 均读取该版本。历史脚本名称中的“测试版”仅描述当时交付状态。0.5.0 起，脚本名称为“咩咩联机大厅 <version>”，构建同时校验 Manifest 版本与发布身份。

0.4.5 命名校准的实际基线为 0.4.5：此前在 0.4.4 基础上完成设置悬停和点击关闭、循环开局仪式，并已在备用账号酒馆启用。Owner 任务书中的 0.4.4 是截图时点；依任务书“以实际代码审计为准”保留 0.4.5，不倒退或提升到 0.5.0。
0.4.5 校准仅为未正式发行开发基线的命名整理。没有执行 Commit、Tag、Release 或远程发布。
已正式发布的附件不得同版本静默替换；未来正式发行前独立检查远程历史与发布状态。

产品版本与存储、房间协议、Runtime API 及机器 Schema 版本相互独立。不得因产品升版自动更改协议或 Schema。
