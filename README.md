# 咩咩联机大厅 / MieMie Multiplayer Lobby

咩咩联机大厅是开发中的 2–4 人 SillyTavern AIRP 工具。由房主运行 AI，队友共享剧情并接收各自的状态栏。房间支持公开与暗行动、队伍聊天及断线恢复。
当前开发基线：0.8.0。唯一版本源为 package.json；构建器校验锁文件及 Manifest，并生成脚本名称和文件名，UI 读取同一版本。
产品作者及生态发起人为 SheepSheep。SheepSheepLab 是官方开发、维护与发布命名空间。
官方源码和测试版安装包通过 [SheepSheepLab/MieMie-Multiplayer-Lobby](https://github.com/SheepSheepLab/MieMie-Multiplayer-Lobby) 提供。
本地执行 `npm ci` 和 `npm run build` 后，可将生成的 `dist/MieMie-Multiplayer-Lobby-Extension-0.8.0.json` 导入酒馆助手全局脚本。在酒馆笑脸中保存 Persona 后，大厅会更新身份。由 0.8.0 房主创建或恢复的地图房间需所有玩家使用 0.8.0 或更新版本。当前仍需验证不同公网网络间的互通和实际模型长回合。
0.5.1 的大厅主标题与其他咩咩工具对齐，副标题实时显示当前打开的单人角色聊天。

## 酒馆版本与运行条件

- SillyTavern 1.14–1.19，已逐版验证 1.14.0、1.15.0、1.16.0、1.17.0、1.18.0 和 1.19.0，搭配酒馆助手 4.11.3。房主使用聊天补全接口，脚本自动适配当前启用的宏引擎。
- TauriTavern（TT 酒馆）2.4.0 的 Android 原生 WebView 已通过成品导入、密码入房、行动提交、多人请求构造及个人状态栏分发验收。测试在模型请求入口返回固定回复，TT 原生模型接口及 iOS、macOS 仍待验收。
- 联机需要客户端支持 WebRTC、WebSocket 与安全环境中的 Web Crypto。浏览器版使用 HTTPS 或本机回环地址。

逐版请求和跨版本联机的验收范围见 [测试记录](TESTING.txt)。

### 跨网连接

默认通过 PeerJS 信令交换连接信息，由 WebRTC 尝试直连。GitHub 的 0.7.2 测试版内置咩咩香港 TURN 地址并自动取得临时凭据。玩家照常用房间号和可选房间密码入房，协商失败时客户端会再尝试仅使用中继一次。角色资源、聊天和行动仍由房主端分发，TURN 转发 WebRTC 数据。服务端模板放在 [server/turn](server/turn)，部署方式见 [服务端说明](server/README.txt)。

自托管时可通过「高级连接设置」指定自己的 `iceServers` 或 `turnCredentialUrl`，既有 `config.iceServers` 配置也可继续使用。连接失败的提示会显示候选类型和 ICE 错误码。

## 加入与换位

加入页使用同一行的房间号和可选密码。验证通过后，房主端按 `user1` 到 `user3` 的顺序分配第一个未锁定的空位，有重连凭据的玩家回到原席位。开局前，来宾点击空位换位并重新准备；房主固定在 `user0`，点击空位锁定或解锁，至少保留两席。开局后，可连接房间并选择离线角色申请接管，由房主批准。

## 地图同步、聊天绑定与续玩

0.8.0 起，地图同时包含房主当前聊天补全预设、预设正则和预设中随附的酒馆助手脚本。房主在绑定对话内改动资源后，大厅比较内容再同步。来宾按内容校验本地地图，世界书名称优先保留原名，与本地同名异内容资源冲突时才加联机后缀。加入后进入房间专用聊天，离开该聊天时恢复此前选择的预设与接口类型。

回合行动球直接显示本轮玩家及其行动，先前剧情收在往轮记录。发起重 Roll 或按楼层创建分支时，发起者计为同意，须在 60 秒内获得本次所有在线玩家同意，至少两人。重 Roll 针对上轮剧情，重新使用原行动。投票分支可选择联机生成并已写入酒馆的任一剧情楼层，保留原聊天，玩家自动打开各自的联机分支。原生发送、重 Roll 和创建分支的界面操作会在联机聊天中拦截。

房主可在「脚本同步」查看角色、预设、全局脚本及回合处理状态。兼容的润色或记忆类脚本可通过 [回合处理 API](docs/ROUND-PROCESSOR-API.md) 接入。全局脚本清单只传名称与作用域，玩家使用各自安装的全局工具。

- 房主先打开单个角色的聊天，再创建房间。房间从建房时绑定这段聊天。建房时也可填写公开的场景简介、规则和开场白。
- 通过验证的来宾接收完整角色卡、头像、角色关联和聊天关联的世界书、随卡脚本和角色正则。来宾的本地酒馆会创建该房间专用的角色副本、世界书和聊天，并打开这段聊天。含随卡脚本或正则时先显示资源清单，并按酒馆提示启用。地图上限为 16 MB。
- 原生输入框在联机对话中锁定。房主与来宾在回合行动球里提交，房主收齐后可发起一次生成。剧情和每位玩家可见的行动及状态栏会写入各自的联机对话。暗行动保留其他玩家行动的私密性。房主过去的聊天、全局脚本、全局预设和账户设置保留在房主酒馆。
- 切换聊天后房间继续在线，可以聊天和提交行动。房主返回原聊天后可开局或生成；若在生成途中切换，已锁定行动可在返回后重试。离开房间后可以继续浏览已经写入本地的剧情。
- 房主可在主大厅标题下看到绑定的角色、对话名称和打开状态。切换聊天后，点「返回联机对话」打开原对话并收起大厅。原对话需要保留在当前酒馆。
- 刷新后，房主从大厅首页点「恢复房主存档」，使用原房间号。来宾页面仍开着时会尝试重连；来宾刷新原标签页可点「重新加入原房间」。有密码的房间需要重新输入密码。恢复功能沿用本地存储，房主须回到原浏览器配置，来宾须保留原入房凭据。
- 来宾主动「离开房间」会停止本机重连。开局前，房主收到退出后释放席位；开局后保留角色与已提交行动，可凭原邀请返回或由房主批准接管。房主点「结束联机」确认后结束房间。

## 与咩咩 Hub 配合使用

启用脚本后，Hub 1.1.0 的蜂窝会显示咩咩联机大厅。可在 Hub 的扩展详情里启用独立悬浮球，两个入口共用当前房间。蜂窝打开时，在大厅内进入回合行动或队伍聊天室。回到酒馆后，可通过两个联机悬浮球继续操作。首次从 0.4.x 升级时，在酒馆助手停用旧脚本，再导入并启用当前版本。

Runtime API 2 已在隔离酒馆环境与 Hub 1.1.0 验证。Managed Package v1 已用真实 Hub 校验器和模拟 Release 单独验证。公开在线分发、Registry 上架与正式发行仍待独立验收。测试边界见 [Hub 兼容性记录](docs/HUB-COMPATIBILITY-0.5.0.md) 和 [测试记录](TESTING.txt)。

命名、稳定身份和版本规则见 [产品身份](docs/PRODUCT-IDENTITY.md) 与 [版本规范](docs/VERSIONING.md)。0.4.5 的校准结果见 [命名记录](docs/NAMING-AUDIT-0.4.5.md)。

咩咩联机大厅 0.1.0 · 可实测版
产品作者：SheepSheep

导入文件：dist/MieMie-Multiplayer-Lobby-0.1.0.json
这是一份酒馆助手脚本，不是酒馆扩展安装链接。打开酒馆助手的脚本管理，导入 JSON 并启用。每位玩家各自导入一份。不要导入到你正在写作的重要聊天里，先新建一段测试聊天。

运行条件
房主：SillyTavern 1.19，启用新宏引擎，酒馆助手 4.11.3 或兼容版本，使用 Chat Completion 接口。实测版本为 ST 1.19.0 + 酒馆助手 4.11.3；更早版本未验证。
来宾：能运行酒馆助手脚本及 WebRTC 的现代浏览器。房间创建与身份校验需要 HTTPS 或 localhost 安全环境。使用独立浏览器配置文件测试多个玩家；同一个浏览器配置文件、同一酒馆地址共享重连凭据。
默认使用 PeerJS 公共信令；没有部署自建中央服务器。真正的跨网连通性取决于网络与 ICE，可在“网络设置”填写自己的 PeerJS / STUN / TURN 配置。未保证所有校园网、移动网或防火墙环境都能直连。

第一次双人实测
1. 房主先打开要玩的角色聊天，选好预设。读取当前 Persona，核对姓名与身份后创建房间。
2. 创建时选择“公开行动”或“暗行动”；创建后固定。至少两人，最多四人，房主是 user0。
3. 把完整邀请码发给队友。队友填写自己的 Persona，选择 user1、user2 或 user3，加入并准备。角色身份描述会共享给整个队伍。
4. 全员准备后，房主点击“开始剧情”，绑定此时的角色聊天并记录起始历史。之后生成时请保持这个聊天打开。
5. 房主先提交行动。其余玩家再各自提交，锁定后不能修改。公开模式显示行动内容；暗行动模式对其他人仅显示“已提交”。
6. 收齐后房主点击“生成共同剧情”。只有房主调用 AI。成功后所有人进入下一轮，在“剧情”页看到相同正文及自己的状态栏。
7. 缺失、重复或错位的状态栏不会发布，房主可重试本轮；重试会再次调用 AI。取消会保留已锁定行动。
8. 大厅内按安全文本显示。想使用已有状态栏美化规则，可点击该轮“写入当前酒馆聊天”，确认后写入一条含本人状态栏的消息。此按钮写入当前聊天，重复点击会重复插入。

暗行动的边界
来宾的实时消息、历史和重连同步数据不会包含其他玩家的输入正文；房主界面也只显示自己行动及他人的提交状态。
第一版由房主汇总、保存并发送模型请求，因此房主设备仍然持有全员行动。这是可信房主模式，不是防房主作弊系统。
共享剧情的保密依靠模型遵循提示。模型可能通过叙述或状态栏误泄露秘密；第一版不承诺模型级信息隔离。不要把聊天室当成秘密行动通道，聊天室始终全员可见。

掉线、接管与聊天
原玩家使用同一浏览器配置文件和邀请码重新加入，恢复原席位，不受下拉框席位选择影响。来宾页面存活时会自动重连，也可点“立即重连”。清除浏览器存储会丢失重连凭据。
离线角色保留。新玩家可用邀请码连接并申请接管离线席位；必须由房主批准。接管继承原角色、状态和已锁定行动，原凭据失效。生成过程中不能接管。
房主刷新后，点“恢复房主存档”重开原房间，队友重新同步。房主需要留在运行中的页面；没有房主迁移。每个浏览器配置文件只保存一份房主房间，新建房间会覆盖旧存档。
聊天室同步房主最近 300 条。房主可手动清空，结束联机也会清空。来宾离开或收到结束通知后清空本机房间视图；重连凭据保留，聊天与剧情不写入来宾持久存储。
剧情存档保存在房主浏览器本地；浏览器配额不足时操作报错并回滚。第一版没有独立导出存档按钮，长期使用前注意此限制。

上下文兼容方式
生成期间临时展开 {{user}} / <user> 为带稳定席位的所有参与者名字，Persona 使用 <user0>…</user0> 等包裹。既有预设、角色卡和世界书文件不被改写。
对世界书主关键词与副关键词中的玩家宏，临时按多个玩家的名字 OR 匹配，保留原副关键词 AND/NOT 结构。没有自动同步来宾私有世界书；使用房主启用的世界书及房主当前 Persona 绑定的世界书。
输入中的宏作为字面文本送给模型，不当作酒馆指令执行。
保留原预设状态栏内部字段，要求每位玩家输出：<userN><status>…</status></userN>。不支持把多个玩家状态混进一个无归属 status 的旧输出；遇到这种回复会要求重试。
房主生成期间不要同时发起其他普通聊天或其他脚本的 AI 生成：酒馆宏钩子在该次生成期间是全局的。第一版不处理工具调用、群组聊天、自动摘要或完整跨扩展兼容。
星链/NPC 好感度逻辑仍由预设承担，本版没有新增好感度引擎。

入口与界面
保留预设管理 1.0.0 的潜航、向内拉出、长按 900ms 拖动和入口 50–150% 大小设置；使用独立存储键。
界面采用深色游戏大厅、四席位卡片、剧情/聊天分页。参考检索与来源见 THIRD_PARTY_NOTICES.txt。
本版为独立脚本。Hub Runtime Compatibility 尚未验收；Managed Package Compatibility 未实现。不能据此宣称支持 Hub 在线安装或更新。

验证记录
见 TESTING.txt。四人传输与重连使用真实本机 WebRTC；模型接口返回使用固定测试回复，没有调用付费模型。跨公网实测和真实模型长回合验证仍待实际游玩。
